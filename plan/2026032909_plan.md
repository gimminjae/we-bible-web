# 삭제/나가기 확인 모달 공통화 및 react-confirm 도입

## 1. 프롬프트 기록

- 프로젝트 전반에서 삭제, 나가기 등 데이터가 삭제 처리될 수 있는 작업은 모두 한 번 더 확인을 받고 진행하도록 수정
- 확인 UI는 `react-confirm` 오픈소스를 사용
- 각 파일에서 `react-confirm`를 직접 호출하지 않고, `useConfirm` 커스텀 훅으로 감싸서 사용

## 2. 분석한 내용

- 현재 프로젝트에는 파괴적 액션이 여러 화면에 분산되어 있고, 일부는 `window.confirm`을 직접 사용하며 일부는 확인 절차 없이 바로 삭제를 수행하고 있음
- 최근 토스트 시스템도 라이브러리를 직접 호출하지 않고 `useToast` 훅으로 감싼 구조로 정리했기 때문에, 확인 모달도 같은 방식으로 공통화하는 편이 프로젝트 일관성에 맞음
- 공용 확인 훅은 비동기 `Promise<boolean>` 형태가 가장 쓰기 좋고, 페이지 단에서는 `if (!(await confirm(...))) return;` 패턴으로 자연스럽게 연결 가능
- 삭제/탈퇴/나가기/제거와 같이 복구 비용이 있는 액션은 확인 대상에 포함하고, 단순 토글이나 편집 저장 등은 제외하는 것이 적절함

## 3. 해당 프롬프트를 완수하기 위한 계획

1. 프로젝트 내 삭제/나가기/제거 계열 액션을 전수 조사해 적용 대상 화면과 로직을 정리한다.
2. `react-confirm`를 설치하고, 프로젝트 공용 UI에 맞는 확인 다이얼로그 컴포넌트와 `useConfirm` 훅을 구현한다.
3. 기존 `window.confirm` 사용처를 교체하고, 확인이 없던 파괴적 액션에도 동일한 훅을 연결한다.
4. 루트 마운트 구조와 스타일을 점검한 뒤 `lint`와 `build`로 동작을 검증한다.
