# 신규 기능 개발
## 교회 기능 개발
### 기능 정리
- '교회' 메뉴 추가
- 하나의 교회는 여러 user를 가질 수 있고, user는 여러 교회에 속할 수 있다. (다대다 관계)
- 하나의 교회는 여러개의 팀을 만들 수 있다. (일대다 관계)
- 팀은 여러 user를 가질 수 있고, user는 교회 내의 한 팀에 속할 수 있다.
- 교회 > user 구조가 될 수도 있고, 교회 > 팀 > user 구조가 될 수도 있다.
- 교회의 정보
	- 이름
	- 생성일시, 수정일시
	- 생성한 user의 id
	- 슈퍼 관리자 id
	- 속한 user 수
	- 부 관리자 users의 id 리스트 (이 리스트 안에 포함되는 id를 가진 user는 해당 교회의 부 관리자로 취급 (테이블 필드의 유형은 string으로 하고 "9930, 42930, 2302"형태로 데이터를 저장)
- 팀의 정보
	- 이름
	- 생성일시, 수정일시
	- 생성한 user의 id
	- 팀장의 user_id
- 교회는 교회 내의 users가 모두 공유하는 공통 성경읽기 plan을 만들 수 있다. (plan에 church_id를 넣어줌)
- 팀은 팀 내의 users가 모두 공유하는 공통 성경읽기 plan을 만들 수 있다. (plan에 church_id, team_id를 넣어줌))
- 슈퍼 관리자와 부관리자는 가입 신청 리스트를 보고 승낙을 할 수 있음

### 페이지별 기능
#### 교회 리스트
- 자신이 속해있는 교회 리스트를 볼 수 있음
- 교회 이름을 검색해서 가입 신청
#### 교회 상세
- 해당 교회의 상세 정보 노출
- 세 개의 탭
	- 회원 리스트
		- 슈퍼 관리자는 부관리자 권한 부여/강탈 가능
	- 성경읽기 계획 탭
		- 교회에 속한 성경읽기 계획 리스트를 노출
	- 슈퍼/부 관리자는 성경읽기표 생성/수정 가능. 다만 슈퍼 관리자가 만든 계획(church_id 값 존재, team_id는 null)은 부관리자가 수정 불가 (부관리자가 만든 계획은 church_id, team_id 존재)
	- 팀 리스트
		- 팀에 대한 정보 및 성경읽기계획 리스트 노출
#### 성경읽기 계획 상세
- 계획 상세 정보 노출
- 팀에 속한 계획이라면 팀 정보도 노출
- 속한 팀원 리스트 노출
	- user를 클릭하면 user의 성경읽기 현황을 노출 (진행상황 및 읽기표 UI)
- user들의 성경읽기 현황의 평균 진행도를 노출
